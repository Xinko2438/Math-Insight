## 复用判断

- **直接复用：**现有项目的五页功能与数据边界、原生 navigation-bar 的安全区职责；借用两份 Skill 的设计方法，保留现有绑定、展开逻辑与可见错误反馈作为未来集成约束。
- **结构值得适配：**Photomath 的逐步推导；作业帮/小猿的拍照入口和错题整理路线。借结构，不复制品牌、logo、插图、付费内容或课程入口。
- **仅作研究：**竞品宣传图中的智能体入口与批改；尚未验证的复杂互动不能成为本项目“已实现”依据。
- **不适合当前约束：**整体搬入竞品首页的多学科入口、课程广告、会员销售、家长模块；把 GitHub Web 设计 Skill 视为可直接替代 WXML/WXSS 的运行库；为换皮引入新的 Web 框架或重写后端。

本轮没有复制第三方素材进原型。数学式、图标和界面标记由本项目以文本和代码绘制；不需要装饰性人物照片或生成图片。

## 共同设计规格

- 受众：初高中数学学生，手机上在订正和复习时使用；语气直接、耐心，避免夸大“精准”“秒懂”。
- 主任务：首页开始一道错题；录入页题干和作答紧邻；报告先思考再展开；错题本搜索紧邻列表；学情给出可理解的复习线索。
- 比较基准：每屏 390 × 844 可用视口，同数据、同入口、同字号底线；不以缩小字体或拉长画布制造容量差异。另检查 320 宽窄屏。
- 内容：主示例来自本轮之前真实后台核对的方程 2(x−3)=x+4，错误步骤 2x−x=4−6；答案 x=10。三题变式与答案来自已保存的 PRD 第9节。列表其余七条为明确标注的合成样本，仅用于排版，不能假装有完整诊断。
- 统计：按八条示例记录重算考点/错因次数，不虚构掌握率、排名、连续学习天数或提升幅度。
- 报告调整：把完整错因分析（包含答案）放进独立页签；分步思考默认展示；完整解答与变式答案显式展开。此为 UI 候选，不表示改变了后端输出质量。
- 不新增未实现能力：变式仍在纸上作答、自行核对，不伪造自动批改；拍照用说明弹层表达真实入口但不申请权限；追问展示现有空回复的失败态，不伪造 AI 对话成功。
- 原型不用 iPhone 外壳或手画系统状态栏，呈现微信小程序的可用内容区。导航胶囊仅为原型示意，不替代原生运行时。
- 可读性：正文 14–15px，重要操作 15px 以上，辅助标签不小于12px；可滚动内容；键盘可见焦点；不依赖悬浮反馈；尊重 reduced-motion。

## 2026-11-01：去 AI 味调研与五页复评

### 结论与本轮范围

当前实现把学生日常录题、复看、查找的工具界面，组织成了“大标题—劝导句—大色块—再解释”的宣传页。重复文案占据高价值空间，图标、短标签、文字操作之间又缺少舒适的局部距离。删除几句口号后仍需重排任务和空间，单独换字体、颜色或圆角不能解决。

本轮按用户要求先调研高星开源 Skill，再使用本地 **huashu-design 3.1.0** 的 `critique-guide.md`、`app-prototype.md` 与验证手册复评。只读查看用户附件、既有五页原生截图和对应 WXML/WXSS；没有开启/控制用户窗口，没有运行新模型、安装所研究项目、执行其二进制或修改原生/后端代码。没有产出新视觉初稿，因此本轮不触发新设计的三方向门，也没有把既有蓝色选择当作所有布局的永久批准。

“AI 味”在这里指缺少任务判断、反复套用默认表达的设计观感，不能用来证明作品作者身份。下列方法用于找可解释的问题，不是经过校准的 AI 检测器。

### 如何精准定位，而非凭风格贴标签

每个问题必须记录：**具体位置 → 当前文字/画面 → 对学生任务的影响 → 最小候选修改 → 复查方法**。只命中一个颜色、字体、圆角或句式时，不自动判定失败；先看它是否有信息或操作作用。

| 检查 | 实际问法 | 本项目已看到的证据 | 修正方向 |
| --- | --- | --- | --- |
| 页面任务是否匹配 | 学生来这里要做什么？最大的元素是否帮助完成？ | 首页的大标题在表达价值观，真正入口被放到下一块；复看列表更靠后 | 把录入方式、最近题目组织在首屏，品牌表达缩到不妨碍操作的位置 |
| 文案是否增加信息 | 删掉这句，会失去哪条操作、状态、限制或必要解释？ | “真正弄懂”“比记住答案更重要”“一起找到卡住的那一步”“知识就会更牢一点”多次表达同一愿望 | 直接保留动作与必要条件；教学提示放到对应思考步骤，避免首页反复劝导 |
| 装饰是否承载内容 | 它在显示当前题目/状态，还是只是占位？ | 首页倾斜公式是固定装饰，与学生当前题目无关 | 删除这块装饰或让空间服务实际任务；不为补空换成另一张无关插画 |
| 空间是否表达关系 | 同组有无挤压？组间是否比组内更分明？ | 手动录入的铅笔几乎贴字；表单“题目必填”“解题过程选填”连成一串；报告文字动作贴近 | 按可见图形边界检查间距、基线和点击区域，分别处理，不统一扩大所有 margin |
| 是否过量包装 | 普通状态是否被放成大标题、大卡片或大数字？ | 两条错题的统计页放大数字 2；输入页在字段前已有标题、说明、照片入口 | 保留真实数值和必要上下文，降低无助判断的包装权重 |
| 是否存在反证 | 元素是否已经有明确功能，不能按外观误删？ | 步骤序号表示推导顺序；方程标签表示考点；拍照图标是功能入口 | 保留有用的序号、分类与图标；不能把所有编号、标签、图标都列入禁用表 |

**间距的证据边界：** 源码 `.manual-button` 已声明 `gap:22rpx`，截图依然不舒适。声明存在不证明视觉间距正确，也不能仅凭截图断定 Skyline 不支持 gap。后续应读原生运行时坐标，并检查旋转伪元素的可见轮廓；本轮只确认可见问题，不编造兼容性根因或“改成某个数就好了”的结论。

### 调研后按 huashu-design 复评五页

评审依据为用户最新首页附件，以及 `docs/ui-implementation/native-{home,input,result,history,stats}.png` 的既有原生首屏和源码。旧截图中的两条记录是隔离夹具。下面标明观察与候选，不声称看过尚无截图的键盘、长文和错误状态。

| 页面 | 已确认的问题 | 候选处理及保留项 |
| --- | --- | --- |
| 首页 | 大标题、劝导句、拍照卡说明和页尾学习寄语语义重复；固定倾斜公式装饰占空间；手动入口图标近字 | 录入方式直接命名为“拍照录入”“手动录入”；最近题目上移。保留蓝色与真实历史，不新增签到、连续学习天数等未实现功能 |
| 录入 | 标题与说明再次解释录题；“题目必填”“我的解题过程选填”缺少视觉分组；短题时输入容器留白大，主按钮贴近底部导航 | 使用清楚的持久字段名，例如“题目”“我的作答（选填）”；适配短题与多行作答。保留输入容量、错误作答、照片入口和自动保存的真实说明；键盘后能否找到按钮待测 |
| 报告 | “找到这道题的关键一步”的两行标题占据阅读开头；原题/作答大容器使第一步思考下沉；“看提示”“看本步解答”间距不舒服 | 优先呈现本题内容与思考入口，压缩宣传式标题；控制组内间距。保留原题与错误作答的对应关系、默认分步思考、答案折叠；不以简洁为由直接泄露完整答案 |
| 错题本 | 导航已叫错题本，正文再次放大标题与抒情副标题；搜索、筛选、总数与首条记录之间节奏松散 | 搜索/筛选紧邻列表；日期与题干建立清楚层级。保留搜索、考点分类、查看记录及删除确认，避免把普通查找页再包装成欢迎页 |
| 学情 | 标题承诺“看见薄弱点”，现有证据主要是错题次数；大数字 2 比具体考点更突出；首页式口吻延续到统计页 | 以“错题统计”及真实样本量描述当前能力，把高频考点和复习入口放在更有用的位置。保留“次数不等于掌握程度”的解释、真实计数和完整错因树 |

花叔评审六维的本轮结论：**概念/立意**需要改正工具与宣传的混用；**哲学一致性**上蓝色及无装饰字母方块得到保持，但不足以通过；**视觉层级**让说明压过任务；**细节执行**漏掉了局部拥挤；**功能性**已有技术通过证据，但初次使用效率尚未成立；**创新性**不能靠固定公式装饰补足。不给“8.7/10”或“AI 味 86%”等未经校准的精度。

### 不能照抄的规则

- 一些网页/海报评审要求标题达到正文的 2.5–3 倍、固定留白比例或至少若干张真实照片；它们不适合直接约束学生高频工具页。Impeccable 的 Operate 专篇反而允许单一系统字体、较小字号层级差和熟悉组件。
- Taste Skill 的图库和桌面样本中出现过的尺寸、配色频率，不是手机小程序的通用定律。它自己也把手机、加载、错误处理的一部分内容标为 house rule。
- “禁蓝色”“禁所有圆角”“必须用衬线”“不用系统字体才高级”等不进入本项目规范。蓝色是用户已选方向；当前反馈并没有要求换掉它。
- Web 扫描器不能直接验证 WXML/Skyline 的真实绘制。读到 `gap`、`min-height` 或编译通过，都不能替代原生画面；不以空扫描结果假报干净。
- 不把文案去 AI 味做成词语替换表。真实状态、必需提示、教学支架、错误恢复和隐私说明不能为了短而删掉。

### 下一轮必须补上的验收

1. 先为五页各写一个学生任务，再标出首屏应看到的内容与操作；保留原始问题和已实现能力，不捏造功能。
2. 同设备比例、可用视口、正常字号对比前后画面；记录首条题目/首个字段/第一步思考的位置，以及首屏完整可见内容数。不能靠缩小字或拉长画布改善数字。
3. 给图标—文字、必填/选填标记、报告页签和提示动作做局部截图检查。记录真实间距、视觉边界、基线与触控区域；页面总体有留白不代表局部不挤。
4. 按真实原生栈覆盖空态、有记录、长题干、多行公式、键盘弹出、识别/分析中、失败与底部滚动状态。没有截图/交互证据的格子明确写未测。本轮没有补跑这些状态。
5. 先独立写视觉问题，再看技术测试结果；逐项记录“解决/未解决/需要用户判断”。路由、编译和点击通过只记技术层，不能再升级成视觉质量通过。
6. 对照用户这次红框重看所有五页，检查重复口号及局部拥挤有没有复发；最后由用户判断视觉接受。新构图需要三方向时按 huashu-design 执行；同一已选方向迭代的豁免须如实记录。

## 2026-11-01：按研究执行原生修订

用户“继续吧”后，在已选蓝色方向内修订五页，未回写旧原型。首页移除价值口号、固定倾斜公式和页尾寄语，直接显示拍照/手动录入与最近错题；输入页取消重复标题，缩小短题默认输入高度，分开字段名和必填/选填标记；报告移除开场大标题，把两步思考提前，拉开提示/解答操作；错题本从搜索、筛选和记录开始，日期/考点移到题干之后；学情改为错题统计，保留真实总数、次数口径和完整错因分类，取消大数字包装与泛化学习寄语。

### 原生间距回归

在独立 SDK 2.02.2608080、基础库 3.17.6、390×844 逻辑视口测得：旧手动入口图标和文字的实际间距约 0px，尽管源码声明了 gap。已先将“可见坐标间距至少 10px”加入真实原生检查，旧页面明确失败；改用明确的子项 margin 后实测约 12.4px，检查通过。结论限于本次按钮及运行环境，不宣称 Skyline 所有场景均不支持 gap。输入标记与报告动作也增加实际坐标检查，避免把 CSS 声明存在当作已生效。

### 确认未解决的多行输入问题

扩展检查用 827 字、18 段带换行的中英混排题干，底层 value 与输入逐字相等，但独立模拟器画面出现方框。绕过官方截图冻结处理、直接捕获该专用进程的画面，异常仍存在。最小对照将题干设为三行中文/英文，作答设为同内容无换行版本，前者在换行附近出现方框，后者正常。

| 假设/动作 | 实测结果 | 决策 |
| --- | --- | --- |
| 数据或截图接口造成文字损坏；比对 value 并直接捕获 SDK 画面 | 数据完整；直接画面也有异常 | 不将它归为数据丢失或单纯截图缓存 |
| 自动增高过大；试设 max-height | 高度确实受限，但方框仍存在，且增加裁切 | 撤回 |
| 中文字体回退；临时指定中文字体优先 | 仍复现 | 撤回 |
| 空白处理值不匹配；试设 white-space:normal | 仍复现 | 撤回，停止继续叠加样式试改 |

补充对照：报告的四行完整解答也在换行处显示方框，保存的 solution 中换行仍完整。异常不局限于 textarea；证据为 ui-states/report-full-solution.png。

因此仅能确认“当前隔离原生模拟器的带换行文本绘制异常”，尚未证明其具体底层原因、是否由本次修订引入或是否影响真机。不得写成已修复或验收通过，也不为规避它删掉用户换行/内容、遮盖真实输入框或切换渲染架构。对照与失败尝试保留在 `_work/native-automation/ui-states/`，主交付优先展示正常五页。

分析中按钮原先被原生 disabled 样式冲淡；已给主要操作明确状态颜色和文字颜色。变式答案操作补明确左对齐。真实键盘、输入法和真机仍须另验；本次加载画面只通过隔离数据模拟，没有实际发起分析。
