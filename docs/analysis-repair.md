# 分析结果异常：修复与验收记录

## 故障与证据

用户报告照片识别成功后，分析期间持续遮罩，最终显示“解析结果异常”。旧服务日志有两次流式模型输出 JSON 解析失败，随后转为规则兜底；由于旧日志没有请求编号或时间，不能证明它们就是截图中的那一次。隔离回放证实该兜底仍会发送最终结果，单独的后端 JSON 错误不足以解释客户端弹窗。

客户端有两条确定可复现的丢结果路径：小程序环境缺少全局 TextDecoder 时，原代码吞掉解码异常；没有分块回调且最终响应是 ArrayBuffer 时，原代码只接受字符串。两种情况均可在服务端发送完整结果后误报，并一直显示加载遮罩。实际截图对应哪一条，原有证据不足以断言。

## 已实施的修复

- 按 UTF-8 标准增量处理分块，保留跨块的中文及四字节字符；支持完整字符串、完整 ArrayBuffer、尾段和 CRLF 帧。畸形或不完整字节明确失败，保留原题／作答，不保存损坏结果。
- 每次提交使用独立解码器与代次；迟到的旧请求不能写入新提交。结果须与提交的题目一致。网络中断时保留输入，由学生主动决定是否重试；不会自动再发一次可能付费的诊断。
- MiMo 流式使用官方 JSON 对象模式，保留既有 thinking 默认，最大输出预算由 1600 调为 4096，并检查结束原因及完整结束事件。4096 是上限而非实际用量，实际调用可能更慢或消耗更多额度，质量和耗时需真实请求核对。
- 模型不可用时仅返回明确标注的基础复习提示：不强行判断作答有错，不编造错因、完整解答、变式或分数。截图中的 `x=3` 作答经独立核算正确；规则兜底不是 AI 诊断或正误判定。当前成功结果仍写入本地错题本；正确题／基础参考如何归类与统计，留待第 2.3 节的状态设计处理。
- 每次分析产生编号并写入 `server/.runtime/analysis-audit.jsonl`：耗时、上游状态／编号、结束原因、用量、结果来源和安全错误类别。不保存题目、作答、图片、模型回复全文或密钥。编号用于关联用户看到的错误和服务端记录；该记录不能重建未保存的原始模型回复。
