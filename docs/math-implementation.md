# 可编辑数学文档实现与验收

本项目使用原生小程序组件呈现数学文档。当前实现由用户批准的可编辑数学排版计划驱动；真实模型、物理手机及用户最终接受与隔离检查分开记录，当前进度以 PRD 第0／3／5节为准。

## 来源与固定依赖

- KaTeX 0.16.47：数学排版；`@rojer/katex-mini` 1.3.4：转换成小程序 rich-text 节点。
- unified-latex 的 parse/print-raw 1.8.4：只解析表示语法，编辑时使用源位置修改，不计算或化简。
- esbuild 0.28.2 为构建工具，运行时不下载它。构建源在 `tools/math-runtime/`，产物固定在 `微信小程序/vendor/math/`。
- `manifest.json` 给出版本、文件字节数与 SHA-256；20 个匹配版本 WOFF2 字体嵌入 WXSS，没有外部字体 URL。上游许可与 React 适配片段的 Apache-2.0 说明在 `NOTICES.md`。

原生兼容门槛使用手工数学样例，未上传用户照片、未调用真实模型。方程组、分数、根式、分段函数、矩阵、积分、向量、长箭头、角标及集合符号已在独立隐藏模拟器捕获。初版适配器的向量箭头缺失：输出 SVG 依赖 em 尺寸，但 rich-text 图片缺少明确外部尺寸。现在由自己的包装层补充图片尺寸并将 SVG 编码为 data URL，保留上游排版树和公式源码；没有更换排版引擎。

## 文档真值与兼容

文档格式为 `{version:1, blocks:[...]}`。每个块有稳定 id，类型为 `text`（text 字符串）或 `math`（latex 字符串、display 为 inline/block）。文字、换行与独立公式的顺序保留。`math-document.js` 是前后端共用校验与投影源；最多128块，标识唯一，公式有长度／嵌套限制，拒绝外链、HTML、宏定义和文件指令。

- 文档是排版和编辑的真值；节点与语法树可重建，不作为第二份独立内容保存。
- 字符串投影使用明确公式定界符，传给分析模型时保留分母、括号和方程组结构。旧字符串不批量猜测转换；只有明确的 `$...$` 等标记在阅读时排版。
- 新识别请求发送 `format: math-document-v1`。成功响应包含 questionDoc/wrongAnswerDoc、兼容字符串与复核提示；不带 format 的旧请求保持旧协议。非法结构或截断不得当作完整成功，也不自动重复付费调用。
- 原始识别文档在本机草稿的 sourceTranscription 中保留。用户修改后生成新修订，不能自动改写其他位置或学生作答。
- 任务接收可选文档并由同一源生成字符串；幂等指纹包含结构。SQLite 仅增加可空文档列，旧任务的字符串指纹保持不变。删除、到期和墓碑操作同时移除文档正文；不声称擦除物理介质。

## 编辑、恢复与原图

阅读态点选文字／公式打开原生底部编辑层。普通段使用文本输入；常用公式按源位置提供表达式、分子、分母、根号、上下标或逐行字段。符号与结构按钮插入在当前编辑位置，方程组可添加行；复杂且无法确定映射的结构保持原文，不伪装成完整可视化编辑。

键入保存工作副本，90ms 合并预览更新；点“完成”验证公式并成功保存后才更新主文档。撤销保留原字节内容。暂时离开或关闭编辑层后，可继续未完成编辑；点击分析时若有未完成工作副本，先恢复编辑，避免无声分析旧内容。取消新建空公式不会留下空草稿。保存失败和修订冲突保留工作副本与最后有效文档。

原生验证发现，在当前 SDK／glass-easel 与自动化组合中，自定义组件的 Object 属性内嵌套数组出现了索引对象形态，造成阅读态回退为空块。组件接口因此使用 `document-json`／`session-json` 字符串传递，接收方解析并严格校验；编辑基准绑定采用不可变 `baseDocJson`。原始文档继续留在页面和草稿真值中，不把协议中的任意数字键对象强行当数组。此结论限于本次实测环境，不宣称所有物理手机都存在该行为。

验证脚本中的模拟安全随机字节使用普通数组跨过自动化 JSON 边界，正式代码继续接收官方 ArrayBuffer，后者有独立单元检查。模拟 ArrayBuffer 跨边界丢失曾导致请求未发出；调整测试数据表示后，同一原生提交链路恢复。导航回执超时仅在核实目标路由与草稿标识已到达后接受，不重复发送操作。

原图复制到小程序 USER_DATA_PATH，记录中仅保存本机引用。渲染和编辑不请求第三方服务；任务提交不发送本机文件路径。草稿、任务缓存及已保存错题共享引用；仅在没有记录引用且路径确属本功能管理时清理照片。读取引用失败时保守保留文件，文件保存失败时仍保留识别文字并说明原图未保存。几何图和复杂表格通过原图核对，本期不重绘。

## 验证入口

- `node scripts/verify-math.cjs`：固定公式、编辑定位、撤销、结构插入、文档恢复、保存失败、原图引用与隐私边界。
- `node scripts/verify-ocr.cjs`：真实识别处理器＋假模型，包括新旧协议、危险命令及无重试。
- `node scripts/verify-analysis-jobs.cjs`：隔离本机 HTTP＋假模型，包括文档快照／指纹、旧库兼容与正文删除；另保留20秒异步链路。
- `node scripts/inspect-native-runtime.cjs`：腾讯编译器逐文件编译，按实际 @import 收集 WXSS 依赖。
- 独立隐藏实例就绪后 `node scripts/verify-native-math.cjs`：模拟选图与返回、实际原生组件编辑、撤销、退出恢复及报告快照。所有 API 返回在隔离实例内替换，合成小图和临时记录在结束后恢复／删除。
- 同一脚本的 `--corpus` 验证11类公式与实际原生横向滚动；`--widths` 用项目真实样式做320／375／390／430宽度及两种动效偏好的独立浏览器投影检查。后者不等同原生键盘或手机性能。

截图统一进入 `docs/ui-implementation/gallery.html`。静态图片不等同键盘、动效或真机接受；320–430px 宽度、物理手机输入法、首帧性能及真实照片质量须分别记录。源记录与版本可用于以后同条件回归比较；只有固定样例的前后结果改变了后续选择，才宣称形成了已验证的改进。

## 2026-11-02 编辑弹层键盘问题

用户手机图显示聚焦后头部进入胶囊区域、输入框浮到背景上。六字段分式的隔离原生复现中，旧版400px键盘事件将头部推到44.89px，胶囊底部为82px，证实安全区冲突；DOM测量本身没有证实手机原生输入框浮层的全部绘制机制。

原实现同时使用键盘底部偏移和视口百分比上限，未统一键盘覆盖／视口缩小两种坐标。现由 `utils/sheet-layout.js` 根据打开键盘前高度计算可用底边与明确弹层高度；头部固定，内容区使用高度0＋flex约束，当前编辑行局部滚动。聚焦事件没有高度时不清零既有键盘；重开清除旧状态；文字编辑共用同一布局。去掉原生输入框祖先的位移动画，保留淡入淡出。未自动修改公式或新增等待。

同类审查：标签弹层原无整体高度上限，已按胶囊安全区限制短屏高度，列表可收缩；其新建标签使用系统输入弹窗。报告追问框及普通题干／作答框在页面滚动区内，没有手工键盘偏移或输入祖先位移动画，未发现相同实现模式，实体键盘可见性仍需真机核对。

回归入口：`node scripts/verify-math.cjs` 包含覆盖式／缩窗式键盘、短屏、切换字段缺失高度和重开文字编辑。`node scripts/verify-native-math.cjs --keyboard` 使用原生模拟器＋合成高度事件，保留前后几何与截图，并核验测试数据恢复。该脚本不弹出实体键盘，也不证明手机输入法绘制已通过；手机需复测首末字段、文字编辑、收起重开、完成／取消，确认不遮挡且编辑保存。最新产品状态及未完验收统一见 PRD 第0／5节。

## 2026-11-02 手机反馈后的触屏重做

**纠正与根因：**用户手机图否定字符上覆盖输入框的版本。字符通常窄于20px，覆盖输入框有最小宽度；显示范围与点击语义不一致、邻字被遮挡。每次重排还会重建带focus的输入节点；旧pendingError直接拒绝切换。上一轮Element.tap只验证精确元素目标，未验证手指偏差或连续输入，不能作为触屏质量证据。

**依据与选择：**只读检查MathLive官方pointer-input.ts的实际布局边界／近邻选择，以及官方虚拟键盘的单一共享键盘；Desmos官方计算器同样把数字、字母、函数分组。直接保留KaTeX排版／字体和unified-latex源码定位；适配MathLive的点击测量与稳定键盘做法。MathLive网页组件依然不适合直接放进WXML，未新增H5或远程渲染。来源：[MathLive指针实现](https://github.com/arnog/mathlive/blob/master/src/editor-mathfield/pointer-input.ts)、[共享数学键盘](https://mathlive.io/mathfield/guides/virtual-keyboard/)、[Desmos键盘](https://help.desmos.com/hc/en-us/articles/47067799244941-Desmos-Scientific-Calculator-User-Guide)。

**实现：**数学编辑没有原生input覆盖层，选中只改变背景色与细下划线；在固定键盘输入，选中后的首键替换、后续按键追加。源选区独立于渲染节点，裸上下标先保留为组，避免2改为12却变成另一种含义。按一次连续输入合并撤销。中文textarea保留系统输入法，两种编辑不争抢焦点。

触点按最新boundingClientRect计算，字符内部优先，外侧仅在16px水平／18px垂直限度内选最近目标；没有增大字符布局盒或叠放透明按钮。滚动后重新测量。异步测量以序号拒绝旧回调；测量中的按键排到最后选择之后，防止连点后误改前一个目标。实际系统事件走坐标路径；无坐标的官方自动化／无障碍事件仅用其已明确的目标ID。

未完成结构以编辑草稿源码＋受控空位范围保存；空位投影由本机重建，完成前不覆盖最后有效主文档，也不参与分析。允许保留空位切换目标、继续编辑、退出恢复。空位只是未完成编辑状态，不是新的题目正文真值。

**证据与范围：**29项数学检查与40项页面检查通过；腾讯编译通过。`--touch`替代旧`--direct/--fraction/--keyboard`输入框交互测试：两行方程44个中心、边缘及边框外2px坐标，实际原生token／键盘按钮tap，快速10次切换后立即输入，多位数、空分母切换、退出恢复、补齐与保存。逻辑测试另外验证延迟回调顺序、上标多位数与不同同值数字。`--widths`直接使用当前WXSS与数学节点，验证320–430px四种手机尺寸及数字／字母两组键盘，同高且按键≥44px。坐标注入与元素tap均不等同物理手指，手机点中率、复杂式连续操作及最终接受仍待用户复测。

数学全流程9项测试已适配另一个工作流新增的会话接口与URL前缀：使用假login、假session及假模型，恢复原wx方法；没有访问真实推理。工作区公网配置等并发改动保留，未回退。

**后续使用与复盘：**今后修改点选、排版或键盘时运行`node scripts/verify-native-math.cjs --touch`，以同一44点、连续输入、空位恢复断言和相同公式截图比较退化；不能只依赖Element.tap或静态截图再宣称手机交互通过。原始检查JSON在隔离工作目录，展示图进入统一HTML图集。当前是项目级验证改进，尚无跨项目收益证明。

路由：本轮由主代理串行完成；点选状态、排版与同一个隔离实例强耦合，不委派共享写入。并行收益不适用、费用不可见；核验以本节回归与PRD状态为准。

本轮最新`--touch`另通过长公式横向滚动180px后按新位置点选。最新原生图集9张；触点响应记录包含自动化往返，不作为手机200ms性能承诺。普通经验保存因外部项目证据路径不在AI Native工作区被拒绝，本地复盘已保留，没有搬移证据或伪报保存成功。

## 2026-11-02 空位删除与操作顺序修复（PRD 0.27）

授权：侧聊先只读审查并提出计划，用户随后明确“修改”。本轮仅主代理处理现有文件，不接触其他代理、不重启主线程共享模拟器、不调用模型或修改公网配置。

修复前的隔离复现：空上标删除后原样重建，连续无效删除会挤掉40条有效撤销；点A输1、点B输2在回调乱序下得到7+12；输入后立即完成／暂存保存旧值；暂存A后编辑B会覆盖A。用户截图为当前问题证据，未上传用于推理。

实现入口：math-edit.js从现有unified-latex最小树重建上／下标、分数、根式和行范围；删除受控空位时移除对应结构，并在同一次撤销事务内清理刚变空的父结构。保留非空侧及必要括号，不删除无关同值数字。无变化操作不进入历史，连续输入只在已有有效历史组时合并；initialSource不受40条历史裁剪影响。空公式可继续输入，也可完成为当前块删除。常用希腊字母和比较／几何／集合符号共用注册表。
